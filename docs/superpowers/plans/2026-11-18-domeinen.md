# Domeinen (groepering van opleidingen) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Een instelling kan een eigen koppeltabel `opleidingscode → domein` meegeven; het analysebestand krijgt een kolom `domein` en het dashboard filtert en splitst daarop, net als nu op `sector`.

**Architecture:** `domein` gedraagt zich als een tweede `sector`-kolom. Eén nieuwe functie koppelt de tabel aan het analysebestand; `maak_analysebestand()` krijgt een optioneel argument; het dashboard krijgt een extra (optionele) upload, een filter en een uitsplitsing per domein. Zonder tabel verandert er niets.

**Tech Stack:** R, dplyr, Shiny, testthat.

**Spec:** GitHub-issue #58 (Pitch: Domeinen toevoegen).

## Global Constraints

- Geen vaste domeinindeling in het pakket: de indeling komt altijd van de gebruiker.
- `croho_onderdeel` is géén domein; niet als standaard of fallback gebruiken.
- Eén indeling per run (de huidige), toegepast op alle cohortjaren. Indeling per jaar valt buiten deze iteratie.
- Koppeltabel: CSV met kolommen `opleidingscode;domein` (`;` en BOM, zoals `schrijf_analysebestand()`); een data frame mag ook.
- Zonder koppeltabel: geen `domein`-kolom-effect zichtbaar, bestaande output identiek.

## Review Focus

- Opleidingscode in data maar niet in de tabel → `domein = "Onbekend"` en een waarschuwing met het aantal studenten, geen fout.
- Opleidingscode dubbel in de tabel met verschillende domeinen → fout met de dubbele codes genoemd.
- Opleidingscode als tekst vs. getal (voorloopnullen, `"34567"` vs `34567`) → koppelt toch.
- Verkeerde kolomnamen in de CSV → begrijpelijke fout die de verwachte kolommen noemt.
- Dashboard zonder upload van de tabel → domeinfilter en -grafiek niet zichtbaar.
